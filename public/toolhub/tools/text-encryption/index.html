Text Encryption

Encrypt text with real AES-256-GCM: your password is stretched with PBKDF2 (250,000 iterations, random salt) and the output is a single portable base64 string. Decrypt it on the matching tab.

Key derivation uses 250,000 PBKDF2 iterations, which takes about a second \u2014 that delay is what makes brute-forcing expensive. A wrong password or corrupted input produces a clear \u201cdecryption failed\u201d error.

How to use Text Encryption

  1. Encrypt — On the Encrypt tab, type your message and a strong password, then click Encrypt. Copy the single base64 string it produces.
  2. Share or store the output — The output embeds the random salt and IV, so the one string is all you need — send it however you like, but share the password separately.
  3. Decrypt — On the Decrypt tab, paste the string, enter the same password, and click Decrypt. A wrong password gives a clear failure message, never garbled text.

What is Text Encryption?

Text Encryption is password-based file-note-style encryption for text: lock a message with a password and get a portable string that only the same password can open.

How this developer tool works

Your password goes through PBKDF2 (250,000 iterations, SHA-256, random 16-byte salt) to derive a 256-bit key; the Web Crypto API encrypts with AES-GCM and a random 12-byte IV; salt, IV and ciphertext are concatenated and base64-encoded.

Privacy and limits

All crypto runs locally via the Web Crypto API. There is no password recovery — lose the password and the data is unrecoverable by design.

Text Encryption — frequently asked questions

How strong is this encryption?

Very: AES-256 in GCM mode (authenticated encryption) with keys derived by PBKDF2-HMAC-SHA-256 at 250,000 iterations and a fresh 128-bit salt per message. This matches current industry practice for password-based encryption.

What exactly is the output format?

One base64 string containing 16 bytes of salt, then 12 bytes of IV, then the AES-GCM ciphertext (which includes the authentication tag). Because salt and IV travel with the message, no extra bookkeeping is needed.

What happens if I use the wrong password?

Decryption fails cleanly with a “Decryption failed — wrong password or corrupted data” message. GCM authentication means tampered or wrong-key data is rejected, never silently decrypted.

Can I decrypt this outside the tool?

Yes. The format is standard: base64-decode, split salt (16B) / IV (12B) / ciphertext, run PBKDF2-SHA256 (250k iterations) to get a 256-bit key, then AES-GCM decrypt — reproducible in Python, OpenSSL or any crypto library.
