Docker Compose Converter

Paste any docker run command and get a clean docker-compose.yml: ports, volumes, environment variables, restart policy and networks are parsed with a real quote-aware tokenizer.

Supports -p, -v, -e, --name, --restart, --network, -d, -w, --hostname, -u, --expose, --env-file, image and trailing command. Flags it does not understand are ignored with a note.

How to use Docker Compose Converter

  1. Paste your docker run command — Copy the full command — flags, quoted values and line continuations are all handled by a shell-like tokenizer.
  2. Convert — Click Convert to compose. Ports, volumes, env vars, restart policy, network and the image are mapped to compose keys automatically.
  3. Copy or download — Use Copy YAML or Download .yml, save it as compose.yaml next to your project, and run docker compose up.

What is Docker Compose Converter?

Docker Compose Converter turns imperative docker run commands into declarative compose YAML — the first step when moving a container from a shell one-liner into version-controlled infrastructure.

How this developer tool works

A quote-aware tokenizer splits the command, a flag parser maps Docker CLI options to compose keys (ports, volumes, environment, restart, networks…), and a small YAML emitter quotes values that need it.

Privacy and limits

Parsing is fully local. Secrets in -e flags stay in your browser — still, prefer env files over committing secrets to YAML.

Docker Compose Converter — frequently asked questions

Which docker run flags are supported?

-p/--publish, -v/--volume, -e/--env, --name, --restart, --network, -d, -w/--workdir, --hostname, -u/--user, --expose and --env-file, plus the image name and any trailing command. Combined short flags like -dit are recognized.

How are quoted arguments handled?

The input is tokenized like a shell: single quotes, double quotes and backslash escapes (including line continuations) are respected, so -e “GREETING=hello world” parses as one value.

What compose file format is generated?

A modern services: mapping without a version key (Compose Specification format), which current Docker Compose versions expect.

Can it convert multi-container setups?

One docker run command at a time. Paste each container's command separately and merge the resulting services: blocks into one file.
