Undoing things safely

git revert creates a new commit that undoes an old one — safe for shared branches. git reset --hard rewrites history and discards work — only use it on branches nobody else has pulled.

Force-pushing without breaking things

Prefer git push --force-with-lease over --force: it refuses to overwrite commits pushed by someone else after your last fetch, so you cannot silently destroy a teammate's work.

Frequently asked questions

How do I undo the last commit but keep my changes?

Use git reset --soft HEAD~1 to undo the commit while keeping changes staged, or git reset --mixed HEAD~1 to unstage them too.

How do I create and switch to a new branch?

Run git checkout -b <name> or the modern equivalent git switch -c <name>.

What is the difference between git reset --hard and git revert?

git reset --hard rewrites history and discards changes — dangerous on shared branches. git revert creates a new commit that undoes an old one, which is safe for shared history.
