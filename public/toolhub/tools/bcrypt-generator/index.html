How to use Bcrypt Generator


  1. Enter a password and pick a cost factor — Type the password, choose a cost factor (10 is the recommended default; each step up doubles the work), then click Generate hash.
  2. Copy the resulting hash — The 60-character $2b$ hash appears below. Use Copy hash to paste it into your database or config file.
  3. Verify any time — Paste an existing bcrypt hash plus a candidate password in the verify section and hit Verify password to get a definitive match or no-match.




What is Bcrypt Generator?
Bcrypt Generator creates real bcrypt password hashes — the salted, adaptive hashes used by virtually every web framework for storing passwords — and verifies candidate passwords against existing hashes.
How this developer tool works
It loads bcrypt.js from a CDN and calls its hash and compare functions directly in your browser, with the cost factor you select (4–14). Verification uses bcrypt's constant-time comparison, exactly like a server would.
Privacy and limits
All computation is local; closing the tab erases everything. Very high cost factors (14) can take several seconds and briefly use one CPU core. If the CDN fails to load, the tool shows an error instead of a fake result.




Bcrypt Generator — frequently asked questions


Is bcrypt still a good choice for password hashing?
Yes. bcrypt with a cost factor of 10–12 remains a solid, widely-audited choice for password storage. Newer memory-hard options like Argon2id exist, but bcrypt is still recommended by OWASP when Argon2 is unavailable.
Does my password leave my browser when I generate a hash?
No. This page loads the bcrypt.js library and runs the entire hashing computation locally in your browser. Nothing you type is uploaded, logged, or stored.
What cost factor should I choose?
10 is the safe default and what most frameworks use. Use 12 for production login systems if your server can spare ~250ms per login. Each increment doubles the computation time, which slows attackers the same way.
Which hash formats can the verifier check?
Standard 60-character bcrypt hashes: $2a$, $2b$ and $2y$ prefixes, all interoperable. Paste the full hash string exactly as stored.
