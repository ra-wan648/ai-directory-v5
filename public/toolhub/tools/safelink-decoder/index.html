    How multi-pass decoding works
    
  
    Each pass tries three unwraps in order: (1) redirect wrappers — known query parameters like q, url, u, target, dest, or redirect found on search-engine and social-media redirect links; (2) percent-encoding via decodeURIComponent; (3) base64/base64url blocks via atob. Passes repeat until nothing changes, up to 12 layers deep, with loop protection.
    
  
    Limits of browser-only decoding
    
  
    Everything encoded inside the link itself can be unwrapped. A bare short-link code can only be expanded by asking that service's server, which browsers cannot do without extra permissions — for those, the tool will stop and tell you exactly where it got stuck.
    

    


    
  
    Frequently asked questions
    
  
    What is a safe link?
    A safe link is a shortened or wrapped URL (like adfly-style links or redirect-service URLs) that hides the real destination behind encodings and redirect parameters, often to show ads or track clicks first.
    
  
    Why decode a safe link before visiting it?
    Decoding shows you the true destination before you click, so you can spot phishing, malware, or unexpected domains and decide whether the link is trustworthy.
    
  
    Can it resolve every short link?
    It unwraps every encoding layer and redirect parameter present in the link itself. Short links that need a server round-trip to resolve (like a plain bit.ly code) cannot be expanded in the browser alone; the tool will say so.
    
  
    Is this Safe Link Decoder free?
    Yes, it is completely free, runs entirely in your browser, and requires no signup.
